# 命運酒館｜資料庫結構 v1.0

> 更新日期：2026-11-25（v1.0：定案，確認紀錄見第 7 節）
> 用途：PostgreSQL 的全部資料表、欄位、索引、保存期限與 migration 規則。`packages/database`（Drizzle）照本文件寫；AI 不准自行加表或欄位，要改先改本文件。
> 依據：M0 §4-1、M1 §4-1、《遊戲狀態模型》v1.0、《訊息欄位表》v1.0、《合規與上架》§5（保存期限）、《技術規劃》§4-5、§7、《設定檔總表》§16。

---

## 0. 共通規則

| # | 規則 |
|---|---|
| DB-1 | PostgreSQL 版本照《版本鎖定》；本機、CI、雲端同一主版本 |
| DB-2 | 資料表、欄位名稱用 `snake_case`；主鍵用前綴字串 ID（`rm_`、`mt_`、`pl_`…），由伺服器產生（ULID 為主體） |
| DB-3 | 時間一律 `timestamptz`（UTC）；遊戲內的毫秒時間在 `jsonb` 裡用整數 |
| DB-4 | **只增不改**的表：`events`、`commands`、`snapshots`；沒有 `UPDATE`／`DELETE` 的程式路徑；例外只有第 4 節列的清除工作（整局刪除、結束後快照精簡、測試對局清除） |
| DB-5 | 事件、命令、快照、`matches.state_version` 在**同一個交易**寫入（M1-R03） |
| DB-6 | Token 只存 SHA-256 雜湊；種子只有伺服器與 admin 讀得到（API 層過濾，不回傳給玩家或主螢幕） |
| DB-7 | `jsonb` 欄位寫入前一定先通過 Zod（遊戲狀態模型、訊息欄位表）；讀出後也先驗證 |

## 1. 資料表一覽

| 表 | 用途 | 建置 | 保存 |
|---|---|---|---|
| `rooms` | 房間（開房、房間碼、狀態） | M0 | 對局結束 7 天後刪除（D4） |
| `room_members` | 加入房間的裝置與座位 | M0 | 同 `rooms` |
| `sessions` | Session Token（雜湊）、角色、到期、撤銷 | M0 | 到期後 7 天刪除 |
| `join_tokens` | 一次性 Join Token（雜湊）、到期、使用時間 | M0 | 到期後 1 天刪除 |
| `matches` | 對局：種子、承諾、模式、版本、狀態 | M1 | 1 年（第 4 節） |
| `match_players` | 對局的玩家：座位、暱稱、職業、匿名 ID | M1 | 1 年 |
| `events` | 領域事件（含遙測事件，`visibility: admin`） | M1 | 1 年 |
| `commands` | 命令紀錄與結果（冪等、重播） | M1 | 1 年 |
| `snapshots` | 狀態快照＋雜湊 | M1 | 對局中全留；結束後精簡（D3） |
| `outbox` | 可靠的延遲工作（計時器、通知） | M1 | 處理完 7 天後刪除 |
| `match_summaries` | 匿名統計（對局刪除後保留） | M7a | 永久 |
| `host_reclaim_codes` | 轉移主螢幕的一次性接回碼（雜湊） | M8 | 到期後 1 天刪除 |
| `admin_audit` | 後台操作紀錄（登入、覆寫、轉移、測試控制） | M8 | 1 年 |

- **不建的表**：帳號（MVP 沒有帳號）、遙測獨立表（遙測走 `events`，技術規劃 §13）、回滾與驗證檔相關表（簡化後端已刪）。

## 2. 欄位

### 2-1 房間與連線（M0）

```sql
rooms (
  id                text primary key,          -- rm_…
  code              text not null unique,      -- 6 碼短碼；房間刪除後可重用
  status            text not null,             -- lobby | in_match | ended | closed
  host_session_hash text not null,
  created_at        timestamptz not null default now(),
  ended_at          timestamptz
)
room_members (
  room_id    text not null references rooms(id) on delete cascade,
  player_id  text not null,                    -- pl_…（同一房間內唯一）
  role       text not null,                    -- host | player | spectator
  nickname   text,
  seat       smallint,                         -- 1～4；host 為 null
  joined_at  timestamptz not null default now(),
  removed_at timestamptz,
  primary key (room_id, player_id),
  unique (room_id, seat)
)
sessions (
  token_hash text primary key,
  room_id    text not null references rooms(id) on delete cascade,
  player_id  text not null,
  role       text not null,                    -- host | player | admin
  expires_at timestamptz not null,
  revoked_at timestamptz
)
join_tokens (
  token_hash text primary key,
  room_id    text not null references rooms(id) on delete cascade,
  expires_at timestamptz not null,
  used_at    timestamptz
)
```

### 2-2 對局（M1）

```sql
matches (
  id               text primary key,           -- mt_…
  room_id          text references rooms(id) on delete set null,  -- 房間 7 天後刪除，對局保留 1 年
  mode             text not null,              -- battle_royale | fixed_rounds
  play_mode        text not null,              -- test | official
  seed             bytea not null,             -- 32 bytes；只有伺服器與 admin 可讀
  seed_commitment  text not null,
  content_version  text not null,
  content_hash     text not null,
  config_hash      text not null,
  feature_flags    jsonb not null,             -- 開局時的 features.yaml
  schema_version   smallint not null,          -- GameState schemaVersion
  state_version    integer not null default 0, -- 最後一筆事件的 stateVersion（同交易更新）
  status           text not null,              -- in_progress | paused | ended | abandoned
  started_at       timestamptz not null,
  ended_at         timestamptz
)
match_players (
  match_id    text not null references matches(id) on delete cascade,
  player_id   text not null,
  anon_id     text not null,                   -- 匯出遙測用的匿名 ID（隨機，不可回推）
  seat        smallint not null,
  nickname    text not null,                   -- 開局時的快照
  class_id    text,
  primary key (match_id, player_id),
  unique (match_id, seat)
)
events (
  match_id      text not null references matches(id) on delete cascade,
  state_version integer not null,
  event_id      text not null unique,
  event_type    text not null,
  event_version smallint not null,
  visibility    text not null,                 -- public | owner | peek | admin
  owner_id      text,
  viewer_ids    text[],
  data          jsonb not null,
  causation_id  text,                          -- 命令的 messageId
  state_hash    text not null,                 -- 套用後的完整雜湊
  occurred_at   timestamptz not null,
  primary key (match_id, state_version)
)
commands (
  message_id   text primary key,               -- 冪等鍵
  match_id     text not null references matches(id) on delete cascade,
  player_id    text not null,                  -- 'system'、'bot' 或 pl_…
  command_type text not null,
  payload      jsonb not null,
  result       jsonb not null,                 -- accepted { stateVersion, eventIds } 或 rejected { code }
  received_at  timestamptz not null
)
snapshots (
  match_id      text not null references matches(id) on delete cascade,
  state_version integer not null,
  state         jsonb not null,                -- 完整 GameState
  state_hash    text not null,
  created_at    timestamptz not null,
  primary key (match_id, state_version)
)
outbox (
  id           bigserial primary key,
  match_id     text references matches(id) on delete cascade,
  kind         text not null,                  -- prompt_deadline | presentation_guard | takeover | purge …
  due_at       timestamptz not null,
  payload      jsonb not null,
  created_at   timestamptz not null default now(),
  processed_at timestamptz
)
```

- `commands` 也記被拒絕的命令（冪等需要）；`player_id` 為 `system`／`bot` 的是系統命令（訊息欄位表 §1）。
- 截止時間與保底在 `GameState` 裡也有（遊戲狀態模型 §15），`outbox` 只是「到時叫醒伺服器」的提醒；重啟時以狀態為準重建（M1-R13）。

### 2-3 統計與後台（M7a、M8）

```sql
match_summaries (
  match_id        text primary key,            -- 原對局 ID（對局刪除後仍保留，只是對不到明細）
  ended_at        date not null,               -- 只到日期
  mode            text not null,
  content_version text not null,
  duration_min    integer not null,
  rounds          integer not null,
  win_route       text not null,
  winner_class    text,
  per_player      jsonb not null               -- [{ anonSeat, classId, deaths, cupsDrunk, finalHp, finalGold, noDrinkMode }]（不含暱稱）
)
host_reclaim_codes (
  code_hash   text primary key,
  match_id    text not null references matches(id) on delete cascade,
  expires_at  timestamptz not null,            -- 5 分鐘
  used_at     timestamptz
)
admin_audit (
  id         bigserial primary key,
  action     text not null,                    -- login | override | host_transfer | test_control
  match_id   text,
  reason     text,
  detail     jsonb not null,
  ip_hash    text,                             -- IP 只存雜湊
  created_at timestamptz not null default now()
)
```

## 3. 索引

| 表 | 索引 | 用途 |
|---|---|---|
| `rooms` | `unique(code)`；`(status)` | 加入、清除 |
| `sessions` | `(room_id)`；`(expires_at)` | 撤銷、清除 |
| `matches` | `(room_id)`；`(status)`；`(ended_at)` | 恢復進行中對局、保存期限 |
| `events` | 主鍵 `(match_id, state_version)`；`(match_id, event_type)` | 重建、遙測匯出 |
| `snapshots` | 主鍵；查「某對局最新一筆」用 `order by state_version desc limit 1` | 重建 |
| `commands` | `(match_id, received_at)` | 重播 |
| `outbox` | `(processed_at, due_at)` 部分索引：`where processed_at is null` | 排程 |

## 4. 保存期限與清除（`outbox` 的 `purge` 工作，每天一次）

| 對象 | 規則 | 依據 |
|---|---|---|
| 結束超過 1 年的對局 | 先寫 `match_summaries`（如果還沒有），再刪 `matches`（連帶刪事件、命令、快照、玩家） | 合規與上架 L5 |
| 房間 | 對局結束 7 天後刪除（D4）；對局的 `room_id` 改成 null | — |
| Session、Join Token、接回碼 | 到期後 1～7 天刪除 | — |
| 伺服器日誌 | 不在資料庫；主機日誌保存 30 天 | 合規與上架 L5 |
| 刪除請求 | 後台依對局 ID＋座位刪除該玩家的暱稱（改成「已刪除」）；事件內容只有 ID 與數值，不需要改 | 合規與上架 §5 |

| 結束的對局的快照 | 精簡：只留最後一份＋每 30 事件一份（D3） | 容量（第 6 節） |
| 測試模式對局（`play_mode = test`） | 每週刪除結束超過 7 天的 | 開發期容量 |

- 這些清除是 DB-4「只增不改」的例外：只能整局刪或刪快照，**不能刪或改單筆事件、命令**。

## 5. Migration 規則

| # | 規則 |
|---|---|
| MG-1 | 用 Drizzle Kit 產生；**已經套用到任何環境的 migration 不准修改**，要改就新增一個 |
| MG-2 | 只往前（不寫自動的 down migration）；每個 migration 的 PR 寫明「出問題時怎麼手動復原」（D2） |
| MG-3 | CI 跑兩種：全新資料庫從頭套用；以及「上一個版本的資料庫＋測試資料」再套用新的 |
| MG-4 | 破壞性變更（刪欄位、改型別）分兩步：先加新欄位並雙寫 → 下一個版本再刪舊欄位 |
| MG-5 | 任何 migration 都是 🔴 審查 |
| MG-6 | `GameState` 結構變更不靠資料庫 migration（`state` 是 `jsonb`），靠 `schemaVersion`＋快照升級函式（遊戲狀態模型 G6） |

## 6. 容量估算（Neon 免費方案約 0.5 GB，以官網為準）

| 項目 | 估算 |
|---|---|
| 一局事件 | 約 150 次行動 × 平均 15 個事件 ≈ 2,000～3,000 筆，每筆約 0.5 KB → 約 1.5 MB |
| 一局快照 | 對局中：每 30 事件＋每次行動結束 ≈ 150～250 份 × 約 30 KB ≈ 5～7 MB；結束後精簡成約 100 份以內（D3） |
| 一局命令 | 約 1,000 筆 × 0.3 KB ≈ 0.3 MB |
| **合計** | 對局中約 7～9 MB；結束後精簡成約 2～5 MB／局 |

- 灰盒 30 局：精簡後約 60～150 MB。開發期的測試對局用 `play_mode = test`，每週清除一次（不受 1 年保存）。
