# M4｜卡牌內容

> **2026-11-25 階段調整**：拆成 **M4a**（第一階段：小牌、試煉、冥界、4 個星座）與 **M4b**（第二階段：MVP 大牌 7 張與神殿格）。核心版期間神殿格暫時當酒館。所有 Godot 需求（例如 R18 `card_reveal`）移到第二階段；第一階段由文字版主螢幕顯示結果。

## 1. 目標與範圍

**目標**：把 MVP 的卡牌全部轉成 YAML，並接上對應格子：酒館（塔羅小牌／冥界事件）、試煉之地（試煉卡）、神殿（塔羅大牌）、星座輪替（4 個 MVP 星座效果）。每張牌都有依設計文件寫成的測試。

| 範圍內 | 範圍外 |
|---|---|
| MVP 塔羅小牌 20 張 × 正逆位 × 3 醉意版本 | 其餘 36 張小牌（MVP 之後；先不進牌庫） |
| MVP 試煉卡 12 張 × 3 醉意版本；對手選擇、佔位對決、配對優先順序 | 其餘 12 張試煉卡 |
| MVP 塔羅大牌 7 張（正逆位、醉意版本、持有與打出規則、反應牌） | 其餘 15 張大牌 |
| （祭司版本已刪除，祭司大招直接用一般版 YAML） | 祭司技能本身（M7） |
| 冥界事件 12 張（資料先做好，M7 接死神追逐） | 死神追逐流程（M7） |
| MVP 星座 4 個：射手、金牛、天秤、天蠍 | 其餘 8 個 |
| 卡牌語系鍵、Godot 翻牌演出、手機卡牌顯示 | 正式卡面美術（可先用文字卡） |

## 2. 前置條件

- G2 閘門通過。
- A 已完成「MVP 卡牌 × 效果元件」對照表，缺少的元件已補進 M3 或列為 scripted handler。

## 4. 技術細節

### 4-1 內容檔案配置

```
content/
├─ config/            數值設定（醉意機率、持續回合、上限…）
├─ maps/
├─ minor/             swords.yaml、wands.yaml、cups.yaml、pentacles.yaml
├─ trial/             trials.yaml
├─ major/             majors.yaml、priest_versions.yaml
├─ netherworld/       events.yaml
├─ zodiac/            zodiac.yaml
└─ i18n/zh-TW/        cards.json、zodiac.json …
```

### 4-2 每張牌的測試格式

```ts
describe('minor.swords.10 萬劍穿心', () => {
  it.each([
    ['upright', 'tipsy',  { selfHp: -10, othersDrink: 1 }],
    ['upright', 'sober',  { selfHp: -10, othersDrink: 1, goldFromEachOther: 5 }],
    ['upright', 'drunk',  { selfHp: -12, othersDrink: 1, soulThresholdDelta: -4 }],
    // 逆位…
  ])('%s／%s', (orientation, tier, expected) => { /* 用固定狀態與種子驗證 */ });
});
```

- 測試名稱用卡牌 ID＋中文名；預期值**逐項對照設計文件表格**，測試檔頂端註明來源章節。

### 4-3 AI 轉檔流程（內容由 AI 協助，但要雙重核對）

1. AI 依設計文件把一個花色轉成 YAML＋測試。
2. 另一個 AI 工具逐格比對 YAML 與設計文件表格，輸出差異表。
3. A 角色人工抽查至少 30%。
4. 數值有疑問時，停下來問企劃，不得自行修正。

## 7. 測試要求

- 每張牌依 4-2 格式測試；試煉卡另測「對手條件找不到人」的情況。
- 星座：每個正負效果至少一個測試，含天秤翻轉只限移動擲骰、天蠍毒最多 2 層與轉移。

## 8. 審查重點

- YAML 數值與設計文件逐格一致（審查者要開兩份文件對照）。
- 有沒有用 scripted handler 偷懶處理本來可以用元件表達的效果。
- 語系描述有沒有改寫數值。

## 9. 限制與禁止

- 不准改設計文件的數值；發現設計文件內部矛盾，記錄成問題交給企劃。
- 不准把 MVP 以外的牌放進正式牌庫（可以放在 `content/_draft/`，不參與編譯）。

## 10. 風險

| 風險 | 對策 |
|---|---|
| AI 轉檔抄錯數值 | 4-3 的雙工具比對＋人工抽查 |
| 某些效果描述模糊 | 已於 2026-11-24 補上共通定義（小牌 §1）；之後再發現的，列成【需要決定】清單交企劃，先標 `pending_design`，不進牌庫 |
