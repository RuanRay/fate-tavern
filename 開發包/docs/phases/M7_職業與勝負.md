# M7｜職業與勝負

> **2026-11-25 階段調整**：**M7a**（第一階段）＝職業 YAML 與時機 R01～R03（聖殿騎士、魔法師、遊俠）、死亡與魂火 R06～R10、大逃殺與固定回合制 R14～R18、手機 R21、遊俠 R25、隨機機器人。核心版期間死亡玩家在神殿也可禱告 +2 魂火（暫代祭壇與冥界商店）；只有血量勝利。**M7b**（第二階段，結束時判定 **G3，約 2029-07**）＝祭司 R04、賭徒 R05、商人、聖物與經濟勝利 R11～R13、模擬器 R19、R26、R27、Godot R20、祭壇 R22～R23、代打 R24，以及 A01～A03、A09～A11 的模擬驗收。

> 本階段結束有**閘門 G3**：機器人跑 1,000 局完整對局無例外、無卡死；平均時長估算落在 2.5 小時 ±20%。

## 1. 目標與範圍

**目標**：做出 6 個 MVP 職業、死神追逐、3 件聖物、所有勝利條件，讓一局可以從開局完整玩到結束；並用規則引擎跑平衡模擬，取代原本的 Python 腳本。

| 範圍內 | 範圍外 |
|---|---|
| 6 職業：開局數值、被動、小技能、大招、冷卻 | 其餘 6 種職業 |
| 死神追逐：魂火來源、冥界事件、作祟、門檻、減半 | — |
| 3 件聖物：拍賣成交 → 回起點繞行 → 配對預設為持有者 → 聖物效果 → 完成勝利 | — |
| 勝利條件：經濟勝利、大逃殺（含時間上限）、固定回合制、同時死亡判定 | 隱藏陣營、團隊勝利 |
| 祭司大招（翻 MVP 大牌、祭司當作自己打出）、祭壇格與技能升級、斷線代打機器人 | — |
| `tools/simulator` 平衡模擬報告 | — |
| 開局流程：選職業 | — |

## 4. 技術細節

- 職業技能用效果元件組成；特殊技能（聖殿騎士被動、命運之輪、魔法陣）用 scripted handler，各有測試。
- 「自己的一周」計數：每位玩家各自的圈數；大招冷卻、追獵次數、聖物繞行、死神追逐都用它。
- 機器人策略：隨機合法操作（找卡死）＋簡單貪婪策略（找平衡問題）兩種。

## 7. 測試要求

- 每個職業技能至少 3 個測試（正常、冷卻中、邊界）。
- 死神追逐：門檻隨周數變化、減半進位、寶劍十「所需魂火 −2」。
- 勝利：四種情況各一組黃金劇本。

## 8. 審查重點

- 勝利判定時機是否在整個事件結束後。
- 死亡通則是否優先於卡面。
- 模擬是否直接使用正式規則引擎（不准另寫一套簡化規則）。

## 9. 限制與禁止

- 不准為了讓模擬數字好看而修改規則或數值；結果偏離設計時，回報企劃。
- 不准讓模擬工具依賴伺服器或資料庫（直接呼叫 `rules-engine`）。

## 10. 風險

| 風險 | 對策 |
|---|---|
| 平衡偏離設計 | 模擬報告交企劃決策；數值只改內容檔 |
| 時長超過 2.5 小時 | M8 遙測實測；先找出最耗時的環節（拍賣、賭場、反應窗） |
