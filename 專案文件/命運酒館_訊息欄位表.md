# 命運酒館｜訊息欄位表 v1.0

> 更新日期：2026-11-25（v1.0：定案，確認紀錄見第 10 節）
> 用途：《訊息格式》v1.7 只定了信封、分類和流程；本表定義**每一個命令、輸入請求、事件、演出步驟、小遊戲訊息的欄位**。`packages/protocol` 的 Zod 定義逐條照本表寫；AI 不准自行增減欄位，要改先改本表。
> 範圍：**第一階段（核心可玩版）全部欄位**；第二階段才用到的只列名稱與一句說明（第 9 節），做到時再補欄位。
> 依據：《訊息格式》v1.7、《遊戲狀態模型》v1.0、《設定檔總表》v1.0、《文字版主螢幕》v1.0。

---

## 0. 共通型別

| 型別 | 定義 |
|---|---|
| `PlayerId` | `pl_` 開頭字串 |
| `Ms` | 整數，伺服器毫秒 |
| `Tier` | `sober` \| `tipsy` \| `drunk` |
| `Orientation` | `upright` \| `reversed` |
| `Resource` | `hp` \| `gold` \| `clarity`（魂火用獨立事件 `soul_fire.gained`，E2） |
| `Reason` | `{ kind: ReasonKind; sourceId?: string; frameId?: string; byPlayerId?: PlayerId }` |
| `ReasonKind` | `start_income` \| `card` \| `trial` \| `item` \| `die` \| `skill` \| `zodiac` \| `duel` \| `drink_backlash` \| `haunt` \| `revive` \| `shop_purchase` \| `admin` \| `system` |
| `Targets` | `{ playerIds?: PlayerId[]; cellIndex?: number; instanceIds?: string[] }` |
| 選填欄位 | 用 `?` 表示；可省略。其他欄位必填，沒有值用 `null` |

| `command.end_turn` | player | `{}`（有可選動作時才需要） | M2 |

| 名稱 | `payload` | 用途 |
|---|---|---|
| `system.prompt_timeout` | `{ promptId; appliedChoice: Record<PlayerId, string[]> }` | 逾時用預設值（M1-R12） |

| `bot.respond` | 同 `command.respond`，另加 `{ actingFor: PlayerId }` | 機器人決策（M7a 模擬、M8 代打） |

## 3. 輸入請求（`prompt.request` 的 `kind` 與 `options`）

共通欄位照訊息格式 §7-1。各 `kind` 的 `context` 與 `options[].ref`：

| `kind` | `context` | `options` | 預設 | 階段 |
|---|---|---|---|---|
| `choose_option` | `{ sourceId; frameId }` | 卡面選項，`optionId` 用 `opt:<鍵>`（例 `opt:drink`、`opt:pay`），`ref.preview`＝這個選項的結果摘要語系鍵 | 卡面寫明的預設；沒寫用第一項 | M3 |
| `choose_target` | `{ sourceId; frameId; targetKind: 'player' \| 'cell' \| 'hand' }` | `player:<id>`／`cell:<n>`／`hand:<instanceId>`；選目標所需資訊放 `ref`（例 `ref.gold`） | 依卡面（多半是隨機合法目標） | M3 |
| `blind_pick` | `{ deckId: 'minor' \| 'trial' \| 'nether' \| 'major'; remaining: number }` | `slot:0`～`slot:3`（不含任何牌資訊） | `slot:0` | M4a |
| `deck_peek` | 第二階段（地圖殘頁） | — | — | — |
| `reaction_window` | `{ eventId; sourceId; depth: 0 \| 1 }` | `pass`＋`use:<instanceId>` | `pass` | M3 |
| `pre_roll_window` / `post_roll_window` | `{ rollId; rollerId; dieType; current?: number }` | `pass`＋`use:<dieInstanceId>` | `pass` | M2（空窗）、M6a |
| `accept_risk` | `{ sourceId; frameId }` | `accept`、`decline` | `decline` | M3 |
| `bet` | `{ sourceId; minBet; maxBet; choices: string[] }` | `bet:<選項>:<金額>`、`pass` | `pass` | M4a（佩斯洛） |
| `vote` | `{ sourceId; candidates: PlayerId[] }` | `vote:<playerId>` | 隨機（`misc` 流） | M4a |
| `trade_response` | 第二階段 | — | — | — |
| `lethal_protection` | `{ hpBefore; sources: string[] }` | `use:<sourceId>` | 第一個 | M3 |
| `confirm_drink` | `{ drinkRequestId; cups; reason: Reason }` | `confirm` | 逾時記 `unconfirmed` | M2 |
| `shop` | `{ shopKind: 'normal'; gold: number }` | `buy:<offerId>`、`leave`（可以多次回應，直到 `leave`） | `leave` | M6a |
| `choose_class` | `{ available: string[] }` | `class:<classId>` | 第一個可選的 | M7a |
| `templar_number` | `{ count: 1 \| 2 }` | `n:1`～`n:8` | `n:1` | M7a |

- `shop`、`choose_class`、`templar_number` 是本表新增的 `kind`（E3）：選職業、聖殿騎士選數字、商城購買都用 `command.respond` 回應，不另設專用命令；逾時、重連、代打自動適用。

## 5. 投影（`projection.snapshot`）

- 結構照訊息格式 §9-1；欄位與可見性照《遊戲狀態模型》§18 從 `GameState` 過濾。
- `projection.checksum`：`{ stateVersion; stateHash }`；`stateHash` 只算該角色看得到的欄位。

## 7. 小遊戲訊息

| `messageType` | 方向 | `payload` | 階段 |
|---|---|---|---|
| `minigame.prepare` | 伺服器 → 參加者、主螢幕 | `{ runId; gameId; format; teams; durationMs; prepareMs; params: Record<string, number>; myModifiers?: { kind; effect }[]; role?: 'attacker' \| 'defender' \| 'neutral' }` | M5a |

## 8. 時鐘、連線、管理（第一階段）

- `clock.ping` `{ t0 }`／`clock.pong` `{ t0; serverTime }`；`session.*` 照訊息格式 §5。
- `admin.override` `{ matchId; target: { playerId?; field: 'hp' \| 'gold' \| 'clarity' \| 'soul_fire' \| 'position' \| 'skip_prompt'; promptId? }; value?: number; reason: string }`（M8）。
- `admin.host_transfer` `{ matchId }` → 回 `{ reclaimCode; expiresAt }`（M8）。
- `admin.test_control` `{ matchId; nextDice?: number[]; nextCards?: Record<string, string[]>; fastForwardWeeks?: number }`（M1 起，只限測試模式）。
