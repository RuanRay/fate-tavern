# 審查清單

> 每次審查：**通用清單（G）**＋變更涉及的領域清單。審查報告引用項目編號（例如 `R-07`）。

## G｜通用（每個 PR）

| # | 檢查項目 |
|---|---|
| G-01 | PR 有需求 ID，改動範圍符合 Issue，沒有夾帶無關修改 |
| G-02 | 手寫變更 ≤ 400 行（不含產生檔、YAML 內容、測試資料） |
| G-03 | CI 全綠；沒有 `skip`、`only`、被註解掉的測試；沒有放寬 lint 規則 |
| G-04 | 沒有違反 AGENTS.md §3 架構邊界 |
| G-05 | 沒有違反 AGENTS.md §4 硬性禁止 |
| G-06 | 沒有新增未經 ADR 的執行期依賴 |
| G-07 | 沒有 Token、密碼、`.env` 內容出現在程式碼、日誌、測試快照 |
| G-08 | 顯示文字都走語系鍵 |
| G-09 | 函式 ≤ 60 行、檔案 ≤ 400 行；命名符合規範 |
| G-10 | 註解說明「為什麼」，規則相關程式有引用設計文件章節 |
| G-11 | 沒有假實作、沒有留下無 Issue 編號的 TODO |
| G-12 | 文件矛盾或企劃未定的地方，已用【需要決定】格式提出，而不是自行決定 |

## R｜規則引擎（`packages/rules-engine`、`content`）

| # | 檢查項目 |
|---|---|
| R-01 | 純函式：沒有 I/O、沒有 `Math.random`、`crypto.getRandomValues`、`Date.now`、`new Date(`；亂數只用 `ctx.rng(流名稱)`，整數用拒絕取樣、洗牌用 Fisher–Yates、機率用整數；時間與亂數只來自 `ctx` |
| R-02 | 狀態不可變；沒有修改傳入的 `state` |
| R-03 | 結算順序符合《規則優先序》§2、§3 與《技術規劃》4-7 |
| R-04 | 死亡逐項檢查；勝利在整個事件（含後續觸發）結束後才判定 |
| R-05 | 反應鏈深度上限 2；成本與勝利檢查不可被取消 |
| R-06 | 傷害走管線：替代 → 百分比相加 → 固定值 → 減傷 → 最低 0 → 上限 → 免疫 |
| R-07 | 上限、機率、持續回合、價格等數值來自設定或內容檔，沒有寫死；設定鍵名與《設定檔總表》一致；新功能有 `features.yaml` 開關的開、關兩組測試 |
| R-08 | 綜合資產＝生命×3＋金幣；「金幣最多」等只看單項 |
| R-09 | 百分比無條件捨去、資源不為負、生命不超過上限 |
| R-10 | 清醒反噬不走傷害管線；死亡通則優先於卡面 |
| R-11 | 沒有 `if (cardId === …)` 之類的特例寫在核心；特例在內容或 handler |
| R-12 | 每個規則變更都有引用設計文件章節的測試；測試預期值與設計文件一致（審查者要實際對照） |
| R-13 | 結算堆疊可以在任何輸入請求處序列化並在重啟後繼續 |
| R-14 | YAML 沒有可執行字串；新元件有 schema、文件、測試 |
| R-15 | `GameState` 欄位與《遊戲狀態模型》一致：沒有新增、刪除或改型別的欄位；新狀態、新 `locals` 鍵有 Zod 定義；不變量檢查沒被關閉 |

## P｜協定（`packages/protocol`、`tools/protocol-codegen`）

| # | 檢查項目 |
|---|---|
| P-01 | 只在 Zod 定義一次；產生檔沒有被手改；CI 一致性檢查通過；欄位與《訊息欄位表》逐條一致（沒有自行增減） |
| P-02 | 新訊息有合法與不合法範例；TS 與 GUT 契約測試都通過 |
| P-03 | 破壞性變更有升 `protocolVersion`；非破壞性變更沒有不必要地升版 |
| P-04 | 事件結構變更有升 `eventVersion` 並提供 Upcaster |
| P-05 | 數值全部整數、時間為毫秒整數、ID 有前綴、列舉為 snake_case |
| P-06 | 協定只傳 ID 與語系鍵，不傳顯示文字（玩家暱稱除外） |

## S｜伺服器（`apps/server`）

| # | 檢查項目 |
|---|---|
| S-01 | 外部輸入先 Zod parse；沒有 `as` 強轉未驗證資料 |
| S-02 | 事件寫入成功（交易提交）後才更新記憶體狀態、回覆與廣播 |
| S-03 | 冪等：同一 `messageId` 不重複執行 |
| S-04 | 每個房間命令串行；例外不留下半套狀態 |
| S-05 | 可見性過濾在序列化前完成；主螢幕封包不含 `owner`／`peek`／`admin` 內容 |
| S-06 | 逾時走系統命令並寫入事件（可重播） |
| S-07 | 計時器在重啟後依狀態重建 |
| S-08 | 日誌有 `roomId`、`matchId`、`commandId`、`eventId`；Token 遮罩 |
| S-09 | WebSocket handler 裡沒有遊戲規則 |

## D｜資料庫（`packages/database`）

| # | 檢查項目 |
|---|---|
| D-01 | Migration 可以在乾淨資料庫與現有資料上執行；有說明回滾方式 |
| D-02 | `events` 只增不改；沒有 UPDATE／DELETE 事件的程式路徑 |
| D-03 | 查詢有對應索引（依 `match_id`、`state_version`） |
| D-04 | 交易範圍正確（事件、命令紀錄、快照同一交易） |
| D-05 | Token 只存雜湊 |
| D-06 | 表與欄位和《資料庫結構》一致；`jsonb` 寫入前後都通過 Zod；刪除只出現在保存期限清除工作裡 |

## F｜手機與後台（`apps/mobile-web`、`apps/admin-web`）

| # | 檢查項目 |
|---|---|
| F-01 | 不判定合法性、不計算結果；只顯示伺服器給的選項 |
| F-02 | 倒數以伺服器時間換算；斷線重連後畫面以快照為準 |
| F-03 | 網路資料先 Zod parse |
| F-04 | 直式、單手、大按鈕；主要流程在 iOS Safari、Android Chrome 實測 |
| F-05 | 小遊戲：勝負與係數不在手機端；反應時間用畫面顯示時間 |
| F-06 | 後台所有操作需要登入；危險操作二次確認 |
| F-07 | 手機樣式只用 CSS Modules＋設計代號（CSS 變數）；沒有寫死的色碼、字級、間距；暗色與淺色都能正常顯示（手機介面規範 §5） |

## GD｜Godot（`apps/godot-client`）

| # | 檢查項目 |
|---|---|
| GD-01 | 只有 Godot 4 語法；沒有 `onready`、`yield`、舊 `WebSocketClient`、`Tween` 當節點 |
| GD-02 | 公開函式、成員、訊號參數都有型別；網路資料用產生的 DTO |
| GD-03 | 沒有規則判斷或數值計算（例如自己算起點收入、自己判定勝負） |
| GD-04 | Autoload 只有 `Net`、`Store`、`Clock`、`Presenter`、`I18n` |
| GD-05 | 演出佇列：不認識的步驟跳過並回報；`blocking` 序列播完才回報完成 |
| GD-06 | 地圖由格子順序計算位置，沒有手擺 |
| GD-07 | 3D 骰子停下的點數等於伺服器結果 |
| GD-08 | 沒有每幀做不必要的配置與節點建立；有 Profiler 數據才討論效能改寫 |
| GD-09 | 可重用 Scene 不依賴外部 NodePath；依賴由父層注入、子 Scene 用 Signal 回報 |
| GD-10 | Resource 不存執行中數值；`await`、Timer 回呼後重新檢查節點有效性；`queue_free()` 後不再操作 |
| GD-11 | 演出可被新快照（重連、回滾）中斷並正確收尾；完成回報只送一次 |
| GD-12 | 主螢幕版面、資訊層級、演出時長的修改有決策紀錄（`docs/checklists/03_美術與玩法決策流程.md`） |

> 展開版檢查見 `docs/checklists/02_Godot專用檢查表.md`。

| # | 檢查項目 |
|---|---|
