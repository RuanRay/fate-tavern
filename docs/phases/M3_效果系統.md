> **2026-11-25 階段調整**：R17 Godot 演出步驟移到第二階段；第一階段由文字版主螢幕顯示事件文字。G2 約 2028-04。

## 1. 目標與範圍

**目標**：建立讓所有卡牌、道具、技能、星座都能「用資料描述」的效果系統：受控效果元件、YAML 內容格式與編譯器、選擇對象、條件、輸入請求、反應鏈、傷害管線、致命保護、死亡判定、狀態與持續效果。照《技術規劃》4-7 事件結算引擎實作。

| 範圍內 | 範圍外 |
|---|---|
| 效果元件目錄與執行器 | 具體卡牌內容（M4） |
| `content-schema`、`content-compiler`（YAML → JSON） | 小遊戲本體（M5，本階段用「模擬勝負」介面） |
| 選擇器（目標、排名、綜合資產） | 道具、魔術骰子內容（M6） |
| 條件（醉意階段、生命門檻、正逆位） | 職業技能（M7） |
| 反應鏈（深度 2） | — |
| 傷害管線（含上限 30）、免疫、減傷、轉移、代防 | — |
| 致命保護、死亡判定（逐項）、勝利檢查時機（事件結束後） | 死神追逐內容、聖物（M7） |
| 狀態系統（中毒、暫停、凍結、免疫、同盟、優先配對…） | — |
| scripted handler 註冊機制 | 命定天罰、祭司大招 handler 內容（M7） |
| 手機：通用選擇 UI、反應窗 UI | — |

## 4. 技術細節

### 4-1 效果元件定義（範例）

```ts
const Damage = defineEffect('damage', z.object({
  target: TargetSelector,
  amount: z.number().int().nonnegative(),
  kind: z.enum(['attack', 'dot', 'environment']).default('attack'),
}), (ctx, p) => pipeline.damage(ctx, resolveTargets(ctx, p.target), p.amount, p.kind));
```

### 4-2 YAML 範例（寶劍十正位，含醉意版本；依《MVP卡牌v4》§1-1）

```yaml
- id: minor.swords.10
  kind: minor_card
  orientation: upright
  effects:                          # 基本（微醺）：扣 10 血；其他人各喝 1 杯
    - { type: lose_hp, target: self, amount: 10 }    # 扣血＝代價／自傷，不走傷害管線（MVP卡牌v4 §0）
    - { type: drink, target: others, cups: 1 }
  tiers:
    sober:
      extra:                        # 其他人另外各給你 5 金幣
        - { type: transfer_gold, from: others, to: self, amount: 5 }
    drunk:
      override:                     # 扣血改 15；其他人改各喝 2 杯
        - { type: lose_hp, target: self, amount: 15 }
        - { type: drink, target: others, cups: 2 }
```

### 4-3 結算堆疊

- 堆疊、反應鏈、觸發佇列的欄位照《命運酒館_遊戲狀態模型》§12。
- 用顯式堆疊（不用遞迴）表示「事件 → 子效果 → 觸發」，以便在任何輸入請求處暫停、序列化、重啟後繼續。
- 每個效果實例有唯一 ID；同一事件內每個替代效果最多套用一次。

### 4-4 傷害計算明細

- `damage.applied` 事件要帶計算明細：`base`、`replacedBy`、`percentTotal`、`flat`、`reduction`、`beforeCap`、`final`、`capped`、`immuneReason`。

## 7. 測試要求

- 每個效果元件：正常、目標不存在、目標免疫、資源不足、上下限。
- 性質測試：隨機組合效果，檢查不變量（生命 ≤ 上限、資源 ≥ 0、死亡玩家不被活人效果選中）。
- 重播：每個裁定範例一組黃金劇本。

## 8. 審查重點

- 結算順序是否完全照《規則優先序》與 4-7 流程。
- 有沒有任何「特例」直接寫在引擎核心（應該寫在內容或 handler）。
- 堆疊能否在任何請求處序列化。
- 傷害上限是否讀設定表。

## 9. 限制與禁止

- 不准為了某一張牌在引擎核心加 `if (cardId === ...)`。
- 不准在 YAML 放任何可執行字串。
- 效果元件新增要更新 `content-schema` 與文件，並附測試。

## 10. 風險

| 風險 | 對策 |
|---|---|
| 元件不夠用，大量卡牌需要 scripted | M4 開始前，A 先把 MVP 卡牌逐張對照元件，列出缺口 |
| 結算堆疊難以除錯 | 每一步寫入 debug 事件（`visibility: admin`），重播工具可逐步檢視 |
