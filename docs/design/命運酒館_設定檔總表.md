# 命運酒館｜設定檔總表與功能開關 v1.0

> 更新日期：2026-11-25（v1.0：定案，確認紀錄見第 17 節）
> 用途：所有「不准寫死在程式裡」的數值，**在哪個檔案、叫什麼名字、預設值多少、出處在哪**。AI 實作時照本表建立設定檔與 Zod schema；改數值只改設定檔，不改程式。也包含第一階段暫代規則的**功能開關**。
> 依據：《設定總表》v31、《小遊戲規格》v1.0、《機器人策略》v1.0、《訊息格式》v1.6、《技術規劃》v4.3、《開發檢查表與決策流程》03 §4、《遊戲狀態模型》v1.0。
> 本表的「值」照抄設計文件；兩邊不一致時以設計文件為準，並回報修正本表。⚠️ ＝仍待模擬或灰盒校正的數值。

## 0. 規則

| # | 規則 |
|---|---|
| C0-1 | **兩種設定**：① **遊戲規則設定** `content/config/*.yaml`——會影響結算或重播的數值，編進內容 artifact，算進 `configHash`，開局時記入 `match`；② **伺服器執行設定**——連線、安全、部署，用環境變數＋`apps/server/src/config.ts`（Zod），不影響重播 |
| C0-2 | 鍵名一律 `snake_case`；單位寫在鍵名結尾：`_ms`（毫秒）、`_pct`（百分比整數）、`_gold`、`_hp`、`_cups`、`_turns`（回合）、`_actions`（行動次數）、`_laps`（圈） |
| C0-3 | 值一律整數（機率寫成百分比整數或整數權重）；不准小數。倍率用百分比（`150` ＝ ×1.5） |
| C0-4 | 每個檔案有 Zod schema（`packages/content-schema/src/config/`）；缺鍵、多鍵、型別錯都讓編譯失敗 |
| C0-5 | 卡牌、道具、骰子、職業、星座、聖物的**個別效果數值**不在這裡，寫在各自的內容 YAML（`content/minor/`…）；這裡只放「跨很多內容共用」的系統數值 |
| C0-6 | 對局開始後設定不會變：引擎只讀開局時記下的那一版（`configHash` 對得上才繼續；伺服器更新設定不影響進行中的對局） |
