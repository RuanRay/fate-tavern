# 命運酒館｜效果元件對照表 v2.1

> 更新日期：2026-11-25（v2.1：配合有限牌庫與盲選，修改 `deck_peek`、`redraw` 與地圖殘頁）；2026-11-24
> 卡牌部分的元件、選擇器、狀態見《命運酒館_MVP卡牌v4》第 6 節（以下稱「卡牌清單」）。本文件補上**道具、魔術骰子、職業技能與祭壇升級、星座、聖物、死亡玩家道具、復活保留道具**需要的元件，並逐條對照。
> 抽牌本身（有限牌庫、盲選 4 張牌背、多選一沒採用的放回最底部、抽完重洗）屬於引擎核心的**牌庫模組**，不是效果元件；雙子座、鷹眼、重抽只用參數改變抽牌方式（`blind_n` 盲選張數、`reveal_n` 直接翻開張數、`pick` 採用張數）。規則見《設定總表》第 5 節「牌庫與抽牌」。
> 原則：能用元件＋狀態＋觸發點表達的，一律不寫 scripted handler。全專案只有 2 個 scripted handler（第 8 節）。

## 3. `dice_mod` 的操作種類（魔術骰子 21 種＋其他）

| `op` | 說明 | 使用者 |
|---|---|---|
| `reroll` | 重擲，必須採用新結果 | 命運重擲 |
| `add` | 加減固定值（可帶成本：喝酒、清醒值） | 鉛心骰、醉漢骰（＋重擲、喝 1 杯）、詛咒骰、共鳴骰、冥火骰、清醒骰（−1、清醒值 +6%）、遊俠識途 |
| `set` | 直接指定點數 | 欽定骰 |
| `flip` | 最大值 + 1 − x | 翻轉骰、天秤座 |
| `die` | 換骰子種類 | 巨人骰（D12）、侏儒骰（D4）、聖殿騎士大招（D20） |
| `best_of` | 擲 N 次取一個 | 雙生骰、聖殿騎士大招 Lv1 |
| `multiply` | 結果倍增，附帶「停留格不觸發」等旗標 | 疾風骰 |
| `explode` | 擲出最大值時再擲並相加 | 爆擊骰 |
| `swap_with` | 和同一場比較中另一人的結果交換 | 盜運骰 |
| `cash_out` | 放棄結果（視為 1），改得點數 × N 金幣 | 黃金骰 |
| `echo` | 保留這次結果，下一次擲骰直接沿用 | 回聲骰 |
| `seal` | 指定一人這次擲骰不能用魔術骰子 | 封印骰 |
| `lock_all` | 這次擲骰其他人都不能用魔術骰子 | 王權骰 |
| `foresee` | 先看結果，可以採用或送給下一位擲骰者 | 先知骰 |
| `counter` | 反應：取消一張對你的擲骰使用的魔術骰子 | 護符骰 |

- 每位玩家對同一次擲骰最多使用 1 張魔術骰子（規則層限制，不寫在元件裡）。
- 冥火骰的「如果因此停在試煉之地，魂火 +1」寫成 `add` ＋ `on_stop` 條件效果。

## 4. 觸發點（被動、星座、聖物、道具都靠這些掛上效果）

| 觸發點 | 時機 | 使用者（例） |

| `on_duel_resolved` | 攻防分出勝負（含攻守身分） | 天蠍座下毒、命定天罰、魂火 |
| `on_damage_taken` | 受到傷害後 | 永恆之槍 D6 替代（在傷害管線第 3 步） |
| `on_lethal` | 生命 ≤ 0、提交死亡前 | 不老聖杯、鳳凰羽毛、死神逆 |

| `on_revive` | 復活時 | 冥河金幣、遺囑、靈魂匣、傳承印記 |
| `on_drink` | 喝酒結算時 | 金牛座（每杯付 6 金幣） |
| `on_system_gold` | 從系統得到金幣時 | 商人大招 |
| `on_auction_settled` | 拍賣成交時 | 商人被動 |
| `on_casino_settled` | 賭局結算時 | 賭徒被動與小技能 |
| `on_card_drawn` | 抽牌後、結算前 | 祭司小技能、遊俠大招、雙子座 |
| `on_action_end` | 行動結束 | 射手座射箭 |
| `on_week_start` | 全場進入新的一周 | 星座切換、雙子座配對 |

## 7. 逐條對照：職業技能（含祭壇升級）、星座、聖物

### 7-1 職業技能

> 祭壇升級只改參數：YAML 每個技能有 `levels: [Lv0, Lv1, Lv2]` 三組參數；技能等級屬於玩家狀態，死亡時歸零。

| 職業 | 技能 | 表達方式 |
|---|---|---|
| 聖殿騎士 | 被動 | 觸發點 `on_move_roll`：點數 ∈ 選定數字 → `heal 10`＋（Lv0、Lv1）取消這次移動／（Lv2）照常移動；Lv1 選定數字 2 個 |
| | 戒律 | 反應（防守落敗時）：成本 `clarity −6`（Lv2 −4）→ 減傷 10／14／18 |
| | 大招 | `dice_mod(die D20)`；Lv1 改 `best_of 2`；Lv2 每周 2 次；不觸發被動 |
| 魔法師 | 被動 | 條件修正：清醒值 ≥ 70%（Lv1 60%）時造成傷害 +25%、受到傷害 −25%（Lv2 ±35%） |
| | 冥想 | 取消這次移動＋`clarity +12／16／20` |
| | 魔法陣 | `cell_trap`：效果＝陣眼道具的效果；次數 1／2／3；魔法師自己踩到不消耗次數 |
| 商人 | 拍賣操盤 | 觸發點 `on_auction_settled`：`gold(成交金 × D8×2%)`；Lv1 ×3%；Lv2 最少 8% |
| | 收購清醒 | `convert(金幣 → 清醒值, 6:3／5:3／4:3)` |
| | 大招 | `status(system_income_bonus +50% 上限 60、3 回合)`；Lv1 +75% 上限 80；Lv2 4 回合上限 100 |
| 遊俠 | 追獵 | 試煉之地配對覆寫（規則層的「技能」配對優先序）；Lv1 勝利時 `duel_rider damage +5`；Lv2 每圈 2 次 |
| | 識途 | `dice_mod(add ±1／±2)`＋成本 `clarity −3`（Lv2 −2） |
| | 大招 | `status(draw_choice 直接翻開 3 張選 1，其餘放回最底部)`；Lv1 4 張；Lv2 每周 2 次 |
| 賭徒 | 被動 | 條件修正：金錢操作倍率 ＝ 1 ＋ 已降低的清醒值%（上限 75／90%）；Lv2 虧損時只套用一半；另可把清醒值上升改成下降（`choose`） |
| | 小技能 | `status(casino_multiplier ×2)`；Lv1 冷卻 2 回合；Lv2 輸的時候 ×1.5 |
| | 大招 | 以莊家身分開賭局（賭場模組的「莊家＝玩家」模式）；Lv1 每周 3 次；Lv2 可指定 1 人必須參加 |
| 祭司 | 神諭 | 條件修正：星座效果正面 +50／75／100%、負面 +50% |
| | 重抽 | `redraw`；Lv1 新舊兩張選一；Lv2 冷卻 2 回合 |
| | 大招 | **scripted**：`priest.wheel.v1`（翻開大牌牌庫最上面 1 張並以祭司身分發動；Lv2 翻 2 選 1；效果照卡牌元件） |

### 7-2 星座（MVP 4 個）

| 星座 | 表達方式 |
|---|---|
| 射手座 | 觸發點 `on_action_end`：可以 `roll D8`，對 `first_met`（前方）雙數 `damage 10`（不經小遊戲）、單數 `lose_hp(self 3)`；每人每周 3 次；安全區不受影響 |
| 金牛座 | `on_stop_cell(酒館)`：`gold +9`；`on_drink`：每杯 `transfer_gold → 系統 6`，付不出改 `lose_hp 2` |
| 天秤座 | `on_move_roll`：可以 `dice_mod(flip)`，成本 `drink 1` |
| 天蠍座 | `on_duel_resolved`（攻擊勝利）：可以把傷害改成 `status(poison 5×3, 最多 2 層)`；中毒者擊敗別人時可以把毒轉移（`remove_status`＋對方 `status(poison, 繼承剩餘次數)`） |

### 7-3 聖物

| 聖物 | 表達方式 |
|---|---|
| 賢者之石 | 買下時 `upgrade_item(最多 3 個)`；`status(lap_effect: 每次停留 gain_item 普通 1、上限 5)` |
| 不老聖杯 | `status(lethal_guard 2 次：第 1 次留 1 血並 heal 30，第 2 次只留 1 血)` |
| 永恆之槍 | **scripted**：`relic.spear_of_fate.v1`（勝利時 3 顆 D12 依序吸取三種資源；受到任何傷害時基礎傷害改擲 D6） |

### 7-4 祭壇

| 行動 | 表達方式 |
|---|---|
| 升級技能 | 規則層動作：多種資源混合支付（金幣、`lose_hp`、`drink`、道具折價）→ 技能等級 +1 |
| 切換星象 | 成本 `gold −50`＋`drink 3` → `zodiac_switch(自選、未出現)` |
| 聖殿騎士改數字 | 成本 `gold −20` → 重新選定 |
| 小祈福 | `choose`：A 成本 `gold −10` → 三選一；B `roll D8` 分支 |

## 8. scripted handler 清單（全專案）

| handler | 為什麼不能用元件 |
|---|---|
| `relic.spear_of_fate.v1` | 依序吸取三種不同資源，且改寫所有傷害來源的基礎傷害 |
| `priest.wheel.v1` | 流程本身（翻開牌庫頂的大牌、以祭司身分代打出、反應牌改寫、用完洗回牌庫），效果仍走元件 |

- 開發包 AI 規範：scripted handler 上限 15 個；目前 2 個。
