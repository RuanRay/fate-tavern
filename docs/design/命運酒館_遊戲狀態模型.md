# 命運酒館｜遊戲狀態模型 v1.0

> 更新日期：2026-11-25（v1.0：定案，確認紀錄見第 21 節）
> 用途：規則引擎 `GameState` 的**唯一欄位定義**。快照存的就是它；`stateHash` 用它算；投影（`projection.snapshot`）從它過濾產生；AI 實作時**不准自行增減欄位**，要改先改本文件。
> 依據：《設定總表》v30、《規則優先序》v1.4、《效果元件對照表》v2.1、《MVP卡牌v4》§6、《訊息格式》v1.6 §8、§9、《技術規劃》§4-7、§12-5、M1 §4。
> 寫法：下面用 TypeScript 型別表示；實作時在 `packages/rules-engine/src/state/` 以 **Zod** 定義，型別由 Zod 推導；快照從資料庫讀出時一律先通過 Zod 驗證。

---

## 0. 共通規則

| # | 規則 |
|---|---|
| G1 | **純資料、可 JSON 序列化**：只有物件、陣列、字串、整數、布林、`null`；不准有 `undefined`、`Date`、`Map`、`Set`、類別實例、函式 |
| G2 | **全部整數**：生命、金幣、清醒值（0～100）、魂火、百分比（`25` 表示 25%）、時間（伺服器毫秒） |
| G3 | **順序確定**：需要排序的陣列（狀態、手牌、觸發佇列）都有明確的排序鍵；物件鍵在算雜湊時一律排序（M1 §4-3） |
| G4 | **ID 規則**：照《訊息格式》§15（`pl_`、`it_`、`md_`、`mj_`、`fx_`、`pr_`…）；實例 ID 由狀態內的計數器產生（`ids` 欄位），不用亂數也不用時間 |
| G5 | **不存可推導的值**：例如醉意階段可由清醒值算出，就不存；例外是為了效能或可讀性，要在本文件標「快取」並列入不變量檢查 |
| G6 | **版本**：`schemaVersion` 從 1 開始；欄位有破壞性變更就升版，並寫快照升級函式；第二階段的欄位已先定義並放空值，所以第二階段不用升版 |
| G7 | **不存的東西**：連線狀態、Session Token、遙測、顯示文字、演出軌跡細節（這些在伺服器其他層或事件裡） |

```ts
interface MatchMeta {
```

```ts
interface TurnClock {
```

## 5. 玩家

```ts
interface PlayerState {
  playerId: PlayerId;
  seat: 1 | 2 | 3 | 4;
  nickname: string;
  classId: string | null;            // 'class.templar'…；選職業前為 null
  alive: boolean;

  noDrinkMode: boolean;              // 不喝酒開關（只影響現實喝酒確認，不影響數值）
  arrowsThisWeek: number;            // 射手座每周最多 3 箭
  piscesReversesThisWeek: number;     // 雙魚座每周最多 2 次（非 MVP 星座，預留 0）

interface SkillState {
  minor: { level: 0 | 1 | 2; cooldown: number };   // cooldown＝剩餘回合
  ultimate: { level: 0 | 1 | 2; usesLeftThisLap: number };
  passive: { level: 0 | 1 | 2; usesLeftThisLap: number }; // 追獵、拍賣操盤等有次數的被動
  upgradedAtAltarThisStop: boolean;
```

- 綜合資產（生命 × 3＋金幣）、醉意階段、排名都**不存**，用函式算（M3-R13）。

## 7. 狀態與場上效果

### 7-1 玩家身上的狀態

```ts
interface Status {
  effectId: string;              // 'fx_000123'
  statusId: string;              // 'poison'、'jail'、'safe_zone'、'duel_rider'…（效果元件對照表 §2＋MVP卡牌v4 §6-3）
  sourceId: string;              // 來源內容 ID（卡、道具、技能、星座）
  sourcePlayerId: PlayerId | null;
  stacks: number;                // 疊加層數（中毒最多 2）
  duration: Duration;
  params: Record<string, number | string | boolean | string[]>; // 依 statusId 的 Zod 定義驗證
  appliedAtAction: number;
}
type Duration =
  | { kind: 'rounds'; left: number }          // 回合
  | { kind: 'own_actions'; left: number }     // 自己的行動次數（被暫停也算）
  | { kind: 'uses'; left: number }            // 次數
  | { kind: 'until_own_next_action' }         // 安全區、佔位
  | { kind: 'until_event'; event: string }    // 例：下一次經過起點
  | { kind: 'permanent' };
```

- **持續時間的計算方式**：「倒數計數」——每個 `Duration` 存剩餘數，在固定的觸發點（回合結束、該玩家行動結束、使用時）減 1，歸零時移除並產生 `status.removed`。
- 對象死亡時，身上所有狀態移除（設定總表 §2）。

## 12. 結算狀態（可以在任何輸入請求處暫停、序列化、重啟後繼續）

```ts
interface ResolutionState {
  stack: Frame[];                // 顯式堆疊（M3 §4-3）；頂端在最後
  triggerQueue: QueuedTrigger[]; // 後續觸發佇列，依回合順序處理（規則優先序 §3）
  reaction: ReactionChain | null;
  pendingPrompts: PendingPrompt[];
  appliedReplacements: string[]; // 本事件已套用過的替代效果 ID（每個最多一次）
  pendingVictoryCheck: boolean;  // 整個事件結束才檢查勝利
}
interface Frame {
  frameId: string;
  kind: 'event' | 'effect' | 'trigger' | 'duel' | 'damage' | 'death_check' | 'cell' | 'skill' | 'item';
  sourceId: string;
  actorId: PlayerId | null;
  targets: PlayerId[];
  step: number;                  // 這個框架目前做到第幾步
  locals: Record<string, number | string | boolean | string[] | number[]>; // 中間結果（例：擲骰結果、選擇）
  cancelled: boolean;
}
interface ReactionChain { depth: 0 | 1 | 2; originFrameId: string; entries: { playerId: PlayerId; sourceId: string; instanceId: string }[]; }
interface QueuedTrigger { trigger: string; ownerId: PlayerId | null; sourceId: string; orderKey: number[]; payload: Record<string, unknown>; }
interface PendingPrompt {
  promptId: string; kind: string; forPlayerIds: PlayerId[];
  options: { optionId: string; label: string; ref?: Record<string, string> }[];
  min: number; max: number; defaultOptionId: string;
  responseMode: 'any' | 'in_turn_order' | 'all';
  answers: Record<PlayerId, string[]>;
  deadline: Deadline;            // 第 15 節
  frameId: string;               // 回應後交給哪個框架
}
```

- `locals`、`payload` 的鍵與值型別由各元件、各觸發點的 Zod 定義驗證（不准任意塞資料）。

## 19. 不變量（每次 `reduce` 之後檢查；所有環境都啟用，檢查失敗就拒絕該命令〔`internal_error`〕並記錄，狀態不更新）

| # | 不變量 |
|---|---|
| I1 | `0 ≤ clarity ≤ 100`、`gold ≥ 0`、`soulFire ≥ 0`、`0 ≤ position < 28` |
| I2 | 活人 `1 ≤ hp ≤ hpMax`；死亡玩家 `alive = false` 且 `deathChase ≠ null`、手牌只剩 `dead_item` |
| I3 | 每張牌恰好出現在一個地方：某副 `drawPile`、`discard`、某人的 `majors`、或結算中的框架 |
| I4 | 每件聖物最多一位持有者；持有者的 `relicId` 與 `relics[].holderId` 一致 |
| I5 | 所有實例 ID 唯一 |
| I6 | `resolution.reaction.depth ≤ 2` |
| I7 | 金幣守恆：玩家金幣總和的變化＝系統收入 − 系統支出（`systemLedger`） |
| I8 | 暫停中時，所有 `Deadline` 都是 `frozen` |
| I9 | 中毒 `stacks ≤ 2`；技能等級 ≤ 2 |
| I10 | `week = max(1, 活人 laps 最小值)` |
