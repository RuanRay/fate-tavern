# 命運酒館｜文字版主螢幕規格 v1.1

> 更新日期：2026-11-25（v1.1：T23 並列獲勝的名次；v1.0：定案，確認紀錄見第 8 節）
> 用途：第一階段「核心可玩版」的**正式主螢幕**（技術規劃 §12-1）。筆電用 HDMI 接電視，在瀏覽器全螢幕執行；4 位玩家用手機操作。第二階段由 Godot 主螢幕取代。
> 依據：《畫面清單》v1.5（H 系列）、《訊息格式》v1.6、《技術規劃》§12-1、《開發檢查表與決策流程》03 §4 演出時長預算。
> 原則：**資訊和 Godot 版完全一樣，只是不做動畫與美術**。它和 Godot 版一樣是 `role: host`，只收公開投影、只送房主命令、照樣回報演出完成。

---

## 0. 定位與技術

| 項目 | 內容 |
|---|---|
| 程式位置 | `apps/host-web`（React＋Vite＋TypeScript，與手機共用 `packages/protocol` 型別與 `packages/i18n`）；M0 建立。`tools/fake-host`（M1-R16）保留給自動測試，不給玩家用 |
| 執行 | 筆電瀏覽器（Chrome）全螢幕（F11）；1920×1080 為基準，可縮放到 1280×720 |
| 角色 | `role: host`；用 `POST /api/v1/rooms` 開房取得房主 Session Token，存 localStorage（「繼續上一局」用） |
| 字級 | 照畫面清單 §0：內文 32px、數值 40px、標題 56px；四邊留 5% 安全範圍 |
| 圖形 | 只用文字、色塊、框線、簡單 CSS 形狀與 Unicode 符號；**不用圖片素材**（QR 由伺服器提供的 PNG 除外） |
| 顏色 | 4 位玩家各一個顏色＋一個形狀符號（●▲■◆），不只靠顏色區分 |
| 音效 | 5 個 CC0 佔位音效：輪到誰、擲骰、受傷、喝酒、勝利；設定可關 |
| 第二階段之後 | 保留為開發除錯與低規格電腦備援，不再加新功能 |

## 1. 畫面流程

```
T00 啟動／警語 → T01 開房 → T02 大廳 → T03 開局 → T04 主畫面 ⇄（疊加區 T05～T22）→ T23 結算
```

- 編號對應畫面清單的 H 系列（T04 ⇄ H04），方便第二階段逐一替換。
- 疊加區**不蓋住**四角玩家欄；固定出現在地圖中央的「事件區」（見 T04）。


| 區塊 | 內容 |
|---|---|
| 玩家欄 ×4（四角） | 符號＋暱稱、職業名、生命「92/110」＋條、金幣、清醒值「64%」＋醉意（清醒／微醺／爛醉）、狀態文字標籤（中毒 1・剩 2、監獄、安全區、聖物、代打中、斷線）、大招 ✓／✗、小技能冷卻數字；目前行動的玩家欄**亮框** |
| 死亡玩家欄 | 底色改灰，顯示「死神追逐 魂火 5/8・第 1 圈」 |
| 地圖 | 28 個方框排成正七邊形（座標算法與 Godot 相同：依格子順序＋外形計算）；方框內是格子簡稱（起、酒、試、神、商、煉、壇、獄、安、拍、賭）＋編號；棋子是玩家符號，同格多人並排；目前玩家的格子加粗 |
| 頂端列 | 目前星座名＋正負效果各一行摘要、剩餘回合；回合數、周數、距時間上限 |
| 牌庫 | 4 副牌剩餘張數（只顯示張數） |
| 事件區 | 地圖中央；顯示目前的演出步驟或疊加面板（第 3、4 節）；空閒時顯示「輪到 ● 阿哲」 |
| 事件紀錄 | 最近 6 行，格式照《文字內容與引導提示》§3（「誰＋變化」） |
| 等待提示 | 「等待 ● 阿哲 選擇…」＋倒數條；**反應窗只顯示「等待回應中」＋倒數**，不顯示是誰、幾人 |

## 3. 演出步驟的文字呈現

主螢幕收到 `presentation.sequence` 後，依序在事件區顯示每一步，播完送 `presentation.completed`。文字版沒有動畫，所以每步只停留**最短閱讀時間**：

| 演出步驟 `kind` | 文字呈現 | 停留 |
|---|---|---|
| `focus_player` | 該玩家欄亮框；事件區「輪到 ● 阿哲」 | 0.8 秒 |
| `dice_roll` | 大字「🎲 D8 → 3」；`nearMiss` 時先顯示「6…」再變「3」 | 1.2 秒（近失 2 秒） |
| `dice_modify` | 「3 → 5（鉛心骰・小美）」 | 1.2 秒 |
| `move_token` | 棋子逐格跳，每格 0.15 秒；經過起點時起點閃一下 | 每格 0.15 秒，最多 2 秒 |
| `teleport`／`swap_positions` | 棋子直接換位＋一行說明 | 1 秒 |
| `blind_pick_view` | 4 個方框「?」，被選的變亮再翻成卡名 | 翻開 1 秒 |
| `card_reveal` | 卡名、正位／逆位、醉意版本、**結算結果一行**（例「−10 血、其他人各喝 1 杯」） | 2.5 秒 |
| `card_effect`／`float_text`／`bar_change`／`damage_hit`／`heal` | 玩家欄數值旁出現「−10」「+30」2 秒後消失；不佔事件區 | 不阻塞 |
| `damage_hit`（攻防結果） | 「小美 獲勝・阿哲 −13 血（10 ×1.3）」 | 2.5 秒 |
| `drink` | 「其他人各喝 1 杯」＋已確認者打勾（不卡流程） | 1.5 秒 |
| `status_icon` | 玩家欄狀態標籤增減 | 不阻塞 |
| `zodiac_change` | 「星座切換：天秤座」＋正負效果兩行 | 3 秒 |
| `duel_intro`／`duel_result` | 「● 阿哲 ⚔ ▲ 小美・拔河」／勝負 | 1.5 秒／2 秒 |
| `minigame_view` | 見第 4 節 T11 | 跟小遊戲同步 |
| `death`／`revive` | 「☠ 阿哲 倒下了・進入死神追逐」／「阿哲 復活！」 | 3 秒 |
| `soul_fire` | 死亡玩家欄「魂火 +1」 | 不阻塞 |
| `relic_reveal` | 「◆ 小美 得標 永恆之槍・520 金幣」＋繞行剩餘距離 | 3 秒 |
| `deck_shuffle` | 「小牌牌庫重洗」 | 1 秒 |
| `banner`／`wait` | 一行文字／空白 | 依步驟 |
| 不認識的步驟 | 跳過並送 `presentation.skipped` | — |

- 停留時間放 `apps/host-web` 的設定檔；演出速度 1.5x／2x 時等比例縮短。
- 文字版每次行動的演出約 5～8 秒，比 Godot 版預算（≤ 20 秒）短；灰盒的時長數據以 Godot 版為準（第一階段試玩的時長會偏短，判讀時要注意）。

## 5. 開局與結束

| 編號 | 對應 | 內容 | 建置階段 |
|---|---|---|---|
| T00 | H00 | 遊戲名、限制級標識、健康警語兩行、不喝酒開關說明、「我已滿 18 歲」按鈕 | **第一階段不做**；正式版在 M8（手機 P00 同） |
| T01 | H01 | 模式（大逃殺／固定回合制）、演出速度；「繼續上一局」（本機有未結束對局時）；「用接回碼接回」 | M1、M2 |
| T02 | H02 | 大字房間碼、QR、4 個座位（暱稱、連線、已選職業）；「開始」（4 人都選好才能按）、「移除」 | M0、M7a |
| T03 | H03 | 地圖排列（環上逐格出現，總長 2 秒）、種子承諾前 8 碼、第一個星座 | M2 |
| T23 | H23 | 勝利者（並列時全部列出）、勝利路線、名次（並列同名次、後續跳號，《遊戲狀態模型》§17）、統計（擊倒、喝酒杯數、最大一筆金幣、死亡次數）、公開種子 | M7a |
| T24 | H24 | 設定：音效開關、演出速度 | M2 |

## 6. 房主操作

| 操作 | 方式 |
|---|---|
| 暫停／繼續 | 畫面右上按鈕；鍵盤 `P` |
| 跳過目前演出 | 鍵盤 `空白鍵`（送 `presentation.completed`） |
| 移除裝置 | 大廳 T02；對局中從玩家欄右鍵選單 |
| 全螢幕 | 鍵盤 `F` |

- 所有按鈕都要能用滑鼠操作（房主不一定會記快捷鍵）。

## 7. 驗收

| # | 條件 |
|---|---|
| TH-A01 | 在 1080p 電視前 3 公尺，4 位測試者能讀出每個玩家欄的生命、金幣、清醒值與醉意（試玩前檢查） |
| TH-A02 | 封包掃描：文字版收到的內容與 Godot 版的 `host` 投影相同，沒有任何 `owner`／`peek`／`admin` 內容 |
| TH-A03 | 每段 `blocking` 演出都送出 `presentation.completed`，而且只送一次；不認識的步驟送 `presentation.skipped` |
| TH-A04 | 關閉瀏覽器分頁 → 手機顯示暫停 → 重開按「繼續上一局」→ 接回同一局 |
| TH-A05 | 第一階段範圍內的完整一局（大逃殺與固定回合制各一次）可以只靠文字版主螢幕＋4 支手機玩完 |
| TH-A06 | 地圖格子座標和 Godot 版用同一個函式計算（放 `packages/protocol` 或共用工具），兩邊結果一致 |
