## 0. 共通版面原則

| 項目 | 主螢幕（電視） | 手機 |
|---|---|---|
| 基準尺寸 | 1920×1080（素材 2 倍） | 直式 390×844 為基準，支援 360～430 寬 |
| 安全範圍 | 四邊各留 5%（電視可能裁邊） | 避開瀏海、底部手勢列 |
| 最小字級 | 內文 32px、數值 40px、標題 56px | 內文 16px、按鈕 18px |
| 觸控 | — | 主要按鈕高 56px、單手拇指範圍內；重要按鈕放下半部 |
| 風格 | 萊德偉特式粗線平塗；酒館場景用暗暖燭光色票 | 同一套元件與設計代號 |
| 私密資訊 | **永遠不顯示**任何人的手牌、大牌、聖殿騎士數字 | 只顯示自己的 |
| 計時 | 倒數一律來自伺服器 | 同左 |

## 1. 畫面流程

```
主螢幕：H00 啟動 → H01 開房 → H02 大廳 → H03 開局演出 → H04 主遊戲畫面 ⇄（疊加層 H05～H22）→ H23 結算
手機：  P00 年齡確認 → P01 加入 → P02 大廳／選職業 → P03 待機 ⇄ P04 輪到我 ⇄（P05～P25）→ P26 結算
後台：  A01 登入 → A02 房間列表 → A03 房間監看 ⇄ A04～A07
```

- 主螢幕的 H05～H22 是**疊加在 H04 上**的演出或面板，地圖與玩家資訊欄常駐。
- 手機的 P05～P12 是**伺服器送來的輸入請求**（`prompt.request`），會蓋在當下的畫面上，結束後回到原畫面。

## 5. 線框稿的交付規則

1. 每個畫面一個 Figma 畫框，命名用本清單編號（例如 `H04_主遊戲畫面`、`P05_擲骰前後窗口`）。
2. 每個畫面要畫出所有**狀態**：一般、等待中、倒數快結束、停用、錯誤、空的（例如沒有手牌）。
3. 標出每個元件用的是哪個元件庫元件；新元件另外列出。
4. 文字用最長的實際內容測試（例如最長的卡牌效果文字、最長的暱稱）。
