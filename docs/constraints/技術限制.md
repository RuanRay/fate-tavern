# 技術限制

> AGENTS.md §3、§4 是硬性規則；本檔補充可量測的預算與上限。數值有 ⚠️ 的，灰盒測試後可以調整，但要開 ADR。

## 1. 效能預算

| 項目 | 上限 | 量測方式 |
|---|---|---|
| 伺服器處理一個命令（含資料庫交易） | p95 < 50 ms（本機）、< 150 ms（雲端） | Pino 欄位 `durationMs` |
| Node.js Event Loop 延遲 | p95 < 50 ms | `monitorEventLoopDelay` |
| 規則引擎單次 `reduce`（不含 I/O） | < 5 ms | 基準測試 |
| 快照大小 | < 1 MB | 資料庫監控 |
| 單一 WebSocket 訊息 | ≤ 64 KB | 協定驗證 |
| 手機首次載入（壓縮後 JS） | < 500 KB ⚠️ | Vite build 報告 |
| 手機小遊戲幀率 | ≥ 50 fps（中階手機） | 實機量測 |
| Godot 主螢幕 | ≥ 60 fps（1080p）；單一工作每幀 < 2～3 ms | Godot Profiler |
| 拔河狀態延遲（手機 → 主螢幕） | < 300 ms | 遙測 |

## 2. 時間限制

| 項目 | 數值 | 來源 |
|---|---|---|
| 一般選擇時限 | 20 秒 | 技術規劃 T2 |
| 反應窗時限 | 每層 5 秒；全員回應即關閉 | 技術規劃 T2 |
| 小遊戲 | 準備 3 秒＋對決約 10 秒（總計 ≤ 15 秒）；平手加賽每次 ≤ 5 秒 | 設定總表 §7；小遊戲規格 |
| 演出保底 | `maxDurationMs + 3000` | 訊息格式 §10 |
| 心跳／逾時 | 5 秒／15 秒（主螢幕 10 秒，逾時即暫停對局） | 訊息格式 §5；技術規劃 §12-3 |
| 斷線座位保留 | 3 分鐘 | 技術規劃 §4-4 |
| 單局目標 | 4 人局約 2.5 小時 | 設定總表 §1 |
| 演出時長預算 | 系統演出平均每次行動 ≤ 20 秒；各演出上限見決策流程 §4 | 技術規劃 T9 |

## 3. 程式規模

| 項目 | 上限 |
|---|---|
| 單一 PR 手寫變更 | 400 行（不含產生檔、YAML 內容、測試資料） |
| 函式 | 60 行 |
| 檔案 | 400 行 |
| scripted handler | 每個都要有測試；MVP 目前只允許 2 個（AGENTS.md B7），新增要開 ADR；總數 ⚠️ 硬上限 15 個（超過代表效果元件設計不足，需要檢討） |

## 4. 依賴管理

- 執行期依賴要開 ADR（理由、替代方案、授權、維護狀況）。
- 開發依賴在 PR 說明理由即可。
- 授權只接受：MIT、Apache-2.0、BSD、ISC、PostgreSQL License、MPL-2.0（MPL 需註記）；GPL 類不接受。
- `pnpm-lock.yaml` 必須提交；CI 用 `--frozen-lockfile`。

## 5. 安全

- Token：高熵（≥ 128 bit）、只存雜湊、不放網址參數（QR 內的一次性 Join Token 除外）。
- 速率限制：加入 API、短碼嘗試、WebSocket 訊息頻率（⚠️ 每連線每秒 30 則）。
- 管理後台與玩家 API 分開路由與認證。
- 日誌、錯誤追蹤一律遮罩 Token；不記錄玩家輸入內容全文。

## 6. 資料

- 事件只增不改；修正用補償事件。
- 每日備份；每個里程碑至少做一次還原演練。
- 遙測只用匿名 ID 與暱稱，不收集其他個人資料。
