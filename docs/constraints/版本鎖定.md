# 版本鎖定

> M0 開工第一天由 A 角色填寫實際版本並提交；之後升級主版本要開 ADR，在獨立分支驗證。
> 原則：選**當下的穩定版／LTS**，鎖到小版本；不追最新的預覽版。

> **2026-11-25 已填寫**：版本查自 npm registry、endoflife.date、各專案 GitHub Releases（當天的最新穩定版），並核對過彼此的相容範圍（見「選擇理由」欄）。M0 建 `package.json` 時照這裡寫死版本；開工當天如果有新的修補版（第三碼），可以直接改成新的修補版，主版本或次版本變動才要走下方的升級規則。

## 升級規則

1. 開 ADR：為什麼升、影響範圍、回退方式。
2. 獨立分支升級，跑完整 CI＋黃金重播＋崩潰恢復。
3. Godot 升級另外檢查：場景、Shader、匯出、GUT、3D 骰子軌跡播放。
4. 不在里程碑最後一週升級。
