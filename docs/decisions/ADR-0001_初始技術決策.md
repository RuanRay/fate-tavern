# ADR-0001～0006：初始技術決策（彙整）

- 狀態：已採用
- 日期：2026-11-23
- 詳細比較與切換條件見《命運酒館_技術規劃》第 2、9 節。

| 編號 | 決定 | 主要理由 | 重新檢討的條件 |
|---|---|---|---|
| ADR-0001 | 主螢幕用 **Godot 4 穩定版＋靜態型別 GDScript**；不用 C#；C++ GDExtension 只作效能預留 | 免費（MIT）、2D／2.5D 與 UI 整合最好、灰盒迭代快；規則在伺服器，不需要 C# 強化客戶端 | Godot 無法支援必要的 Steam／輸入／SDK；或 Profiler 證明效能瓶頸 |
| ADR-0002 | 伺服器用 **Node.js＋Fastify＋標準 WebSocket（ws）**；不用 Colyseus、Socket.IO | 三端都原生支援標準 WebSocket；協定完全自控；規則與前端共用 TypeScript | 自建斷線恢復與房間管理成本過高（改 Socket.IO）；Event Loop p95 持續超過 50～100 ms |
| ADR-0003 | **伺服器權威＋事件儲存＋快照**（PostgreSQL） | 2.5 小時長局必須能從崩潰恢復、可重播、可審計、可回滾 | 無（核心原則） |
| ADR-0004 | 卡牌內容用 **YAML＋受控效果元件**，特殊效果只能用有測試的 TS handler | 企劃改數值不用改程式；避免演變成不安全的腳本語言 | 非工程人員大量編輯、YAML 錯誤影響效率（改內容編輯器） |
| ADR-0005 | 協定 **Zod 單一來源** → JSON Schema → TS 型別＋GDScript 類別 | 三端不會各寫一份而漂移；契約測試自動化 | 頻寬或序列化成為瓶頸（改 MessagePack／Protobuf） |
| ADR-0006 | 手機與後台用 **React＋Vite＋TypeScript**；手機先網頁，之後可包 App | 免安裝、掃碼即玩；與伺服器共用型別 | 低階手機效能或載入大小成為實測問題（改 Preact／Svelte） |
